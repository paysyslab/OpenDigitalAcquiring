# Settlement and Reconciliation Framework

| Term / Field | Description |
|---|---|
| Primary Transaction ID (TxnID) | Generated at payment initiation. Globally unique, idempotent, stored unchanged across all systems. Acts as: legal financial reference, primary GL reference, dispute reference, audit trace key. Core Wallet enforces uniqueness validation. |
| Settlement Transaction ID (SettlementTxnID) | Generated by MMP when settlement event occurs. Always references the original TxnID. One TxnID may have multiple SettlementTxnIDs (partial settlement, adjustment, refund). Contains settlement type: Credit / Refund / Adjustment. |
| Core Wallet Posting | GL posting occurs instantly on authorization. Ledger entries: TxnID, Timestamp, Channel ID, Authorization Ref, Gross Amount, MDR, Net Amount. |
| Reconciliation Levels | Customer to Core Wallet: Purchase TxnID. Core Wallet to MMP: Purchase TxnID. MMP to Settlement GL: SettlementTxnID. Finance GL to Reports: Purchase TxnID + SettlementTxnID. |
| Control and Audit Guarantees | No system may overwrite Purchase TxnID. SettlementTxnID supports 1:N mapping. Both IDs searchable in Reports, Dashboards, Reconciliation Tools, and Audit Logs. All reconciliation exceptions and resolutions fully audit-logged. |
